三星软重启流畅优化

针对 Samsung Galaxy 系列 One UI 在软重启后可能出现的掉帧、卡顿、系统服务异常以及锁屏时钟 / AOD 丢失问题进行检测、平息与修复的 KernelSU 模块。

本模块主要面向使用临时 Root、KernelSU 进行系统调试或软重启的 Galaxy 用户。

---

核心特性

🛡️ 安全维护模式

2.0.0 重构启动维护逻辑，引入安全维护模式。

模块启动后不会无条件修改系统状态，而是首先对当前系统运行环境进行检查，在确认系统已经完成启动并具备正常的框架运行环境后，再执行后续维护操作。

降低软重启后系统仍处于初始化阶段时进行激进操作所带来的风险。

---

🔍 system_server 状态检测

新增 "system_server" 运行状态检测机制。

模块会检查：

- "system_server" 是否正常运行
- 当前 "system_server" PID
- 系统启动是否已经完成
- 框架服务是否处于可维护状态

只有在满足安全条件后才继续执行维护流程。

避免在 system_server 尚未稳定时进行清理或系统参数处理。

---

🧹 精准清理临时 Root 残留

针对临时 Root / CVE 提权过程中可能遗留的临时进程、脚本和二进制文件进行定向清理。

2.0.0 继续采用路径白名单 + 精确进程识别机制：

/data/local/tmp
/data/tmp
/dev

等临时目录作为主要检查范围。

不会使用危险的：

pkill -f
killall

等模糊匹配方式扫描整个系统。

避免误杀：

- S-Pen 服务
- Samsung 硬件服务
- system_server
- 网络服务
- 电源管理服务
- Android 核心系统进程

---

📊 运行状态日志

2.0.0 增加并完善运行日志。

模块会记录关键维护阶段，例如：

模块启动
系统启动完成
临时 Root 残留检查
system_server 状态
清理结果
维护完成

方便通过 KernelSU 管理器、终端或其他 Root 工具查看模块实际运行情况。

日志不会作为系统核心功能依赖，仅用于故障排查和运行状态确认。

日志默认保存在/storage/emulated/0/Download/Samsung_LagFix/目录下

---

⚡ 开机维护流程优化

重新整理 "service.sh" 执行流程。

相比早期版本：

- 减少无意义的等待
- 减少重复执行
- 减少高开销 PID 轮询
- 使用单次进程状态扫描
- 在系统真正进入可维护状态后执行操作
- 避免 system_server 初始化期间进行激进处理
- 删除了意义不明的试图拉起 AOD 的相关代码

降低模块自身对开机过程的影响。

---

🌐 网络与内核异常平息

保留此前经过验证的网络与内核维护机制，用于缓解软重启后可能出现的异常资源占用。

包括：

- TCP TIME_WAIT 状态处理
- 网络套接字队列优化
- 内核日志洪泛抑制
- kworker 高频占用问题平息

模块不会以强制性能模式替代三星原生调度策略。

---

🧠 虚拟内存优化

保留经过验证的虚拟内存参数：

vm.swappiness = 100
vm.vfs_cache_pressure = 80

用于降低软重启后部分后台服务异常换页造成的系统负载。

不会通过强制提高 CPU 性能或锁定调频来“解决”卡顿。

---

🔋 保留三星原生调度与电池策略

模块不会：

- 强制修改 CPU 调频策略
- 禁用三星后台限制
- 修改应用电池优化白名单
- 强制提高后台进程优先级
- 禁止系统进入省电状态

尽可能保留 Samsung One UI 原生的：

- CPU 调度
- 能效曲线
- 电池优化
- 后台应用策略
- 温控策略

模块的目标是修复软重启后的异常状态，而不是替换三星原生调度机制。

2.0.0 更新日志

v2.0.0 — 重大重构

🛡️ 全面重构启动维护机制

新增安全维护模式。

模块不再单纯按照固定延迟执行全部操作，而是根据系统实际启动状态决定是否进入维护流程。

降低软重启后过早操作系统组件造成异常的风险。

🔍 新增 system_server 状态检测

新增 "system_server" 状态检测。

模块会在维护前确认：

- 系统是否完成启动
- system_server 是否存在
- system_server PID 是否正常
- 当前框架环境是否达到维护条件

避免在 Android Framework 尚未稳定时执行清理操作。

🕐 重构 AOD / 锁屏时钟恢复

重新整理软重启后的锁屏时钟与 AOD 恢复链路。

不再单纯依赖固定延迟，而是在系统状态满足条件后执行恢复操作。

针对软重启后：

- 锁屏时间消失
- AOD 不显示
- AODService 状态异常
- 锁屏组件未重新连接

进行针对性处理。

🧹 重构临时 Root 残留清理

继续采用临时目录白名单机制，并进一步收紧清理范围。

避免使用全局模糊进程匹配。

重点保证带有 S-Pen 的 Galaxy Ultra 等机型不会因为模块清理逻辑误杀系统硬件服务。

📊 新增 / 完善运行日志

增加模块运行状态记录。

现在可以通过日志确认模块是否：

- 正常启动
- 等待系统完成启动
- 检测到 system_server
- 完成临时 Root 残留检查
- 执行 AOD / 锁屏维护
- 正常结束维护流程

方便定位软重启后的问题。

⚡ 优化 service.sh 执行逻辑

重新整理模块启动脚本。

减少重复的进程扫描与无意义等待，并将维护操作按照：

启动
 ↓
等待系统完成启动
 ↓
检查 system_server
 ↓
安全维护
 ↓
临时 Root 残留清理
 ↓
记录日志
 ↓
完成

进行。

🔋 保持原生调度策略

2.0.0 没有重新加入强制性能调度。

继续保持 Samsung 原生：

- CPU 调度
- 电池优化
- 后台限制
- 温控
- 能效策略

避免为了追求“流畅”而牺牲续航和稳定性。

安装

KernelSU 管理器安装

1. 从 Releases 下载最新版本 ZIP。
2. 打开 KernelSU 管理器。
3. 进入「模块」。
4. 点击「+」。
5. 选择模块 ZIP 并刷入。
6. 安装完成后按照实际使用场景执行软重启。

«⚠️ 如果使用的是临时 Root，请注意完整关机 / 冷启动可能导致 Root 状态消失。模块本身不会让临时 Root 永久化。»

---

卸载

直接在 KernelSU 管理器中禁用或删除模块，然后按照提示重启即可。

如果需要排查问题，建议先保留运行日志，不要立即删除日志文件。
